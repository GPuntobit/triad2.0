# Triad website generator — native Triad, no JavaScript

The published website in `docs/` is **static HTML/CSS/SVG**. Browser
JavaScript, third-party script loaders and the former interactive browser
playground have been removed. To execute programs, use the native Linux
x86-64 machine-code seed, e.g. `./bin/triad program.triad`.

## Sources

The page generators are written in Triad-Core:

- `site_pages.td`: documentation pages and static navigation.
- `site_pages2.td`: remaining documentation pages.
- `site_playground.td`: static page explaining native execution, **not** an
  in-browser interpreter.
- `site_style.td`: generated documentation stylesheet.

The POSIX driver `build.sh` executes the generator programs with
`bin/triad`, parses `=== FILE: ... ===` markers and writes only a
strict allowlist of HTML/CSS output paths. It uses no Node/npm/JS. It
rejects generated executable browser scripts and unsafe output paths.

## Use

```sh
sh tools/site-gen/build.sh --dry-run  # execute and validate generators
sh tools/site-gen/build.sh --check    # compare generated bytes to published docs
sh tools/site-gen/build.sh --write    # intentionally overwrite generated docs
sh scripts/no-js.sh                   # verify tracked-tree policy
```

`--write` is deliberately explicit. Re-run `--check` only after
publishing regenerated output. Native seed conformance and the committed
golden tests are still the authority for the language semantics.

## Compatibility limits

This driver does **not** replace the removed development oracle's
cross-interpreter differential testing. The Triad source generators must
work on the actual native S0 seed, and the generator output must remain
HTML/CSS without dynamic browser scripts.

If a native source generator fails on S0, treat it as a failure; do not
introduce a foreign-language fallback. The seed generator for the ELF/PE
machine code is a **separate outstanding native migration milestone**,
documented in `docs/NO_JAVASCRIPT_MIGRATION.md`.
