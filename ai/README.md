# Triad for LLM — generation and verification benchmarks
This directory contains a minimal kit for generating **Triad** code
linguistic model and verify it objectively with conformance.
The idea: the model receives `SYSTEM_PROMPT.md` and a `task.md`, returns a
Triad program; the program is saved as `solution.triad` and `verify.jl`
runs it with stage0, comparing stdout and exit code with the golden ones.
> Developer Tool: Not part of the S0→S4 chain. Conformance
> official remains `conformance/`; here the quality of the generation is measured.
## Structure
```
ai/
  README.md           questo file
  SYSTEM_PROMPT.md    prompt di sistema per il modello
  verify.jl           esecutore/verificatore delle soluzioni
  tasks/
    01_somma/
      task.md         richiesta in linguaggio naturale
      expected.out    stdout atteso (golden)
      expected.code   exit code atteso (default 0)
      solution.triad  codice generato (non committato)
    ...
```

## Workflow
1. Provide the template `SYSTEM_PROMPT.md` + the appropriate `task.md`.
2. The model should return **only** one block of Triad code.
3. Save the contents to `ai/tasks/<case>/solution.triad`.
4. Check:
```sh
node cli/triad-cli.mjs ai verify
```

Output: `PASS`/`FAIL` for case, summary, exit 1 if at least one solution
fails. Missing solutions are `SKIP` (do not fail verification).
For a single case:
```sh
node cli/triad-cli.mjs ai verify --tasks ai/tasks/01_somma
```

## Metrics
- **pass@1**: one generation per task, all green.
- **pass@k**: k attempts per task, the first successful one counts.
- **syntax / runtime / output error**: classify FAILs to understand if
  lacks specification, examples or tooling.
A model that passes the 5 tasks demonstrates knowledge of the Triad-Core subset
used here; does not demonstrate knowledge of the complete language.
## Tasks included
| tasks | covers |
|---|---|
| `01_sum` | `println`, precedence, integers |
| `02_factorial` | functions, recursion, ternary |
| `03_fibonacci` | double recursion |
| `04_strings` | strings, concatenation `*`, `length` |
| `05_closures` | function that returns a lambda with capture |
## Safety
`verify.jl` **runs** code generated by the template. Tasks use the profile
Triad-Core and should not contain effects, but a model can generate loops
infinite or unexpected code: run the test in a VM/container, without network and
with limited resources. Do not paste unverified output into production.
## Current limits
- The seed covers 26/29 Core cases; the verifier uses the **seed**, which
  it is more complete than the seed.
- Complete lists and `elseif` are missing; `string()` covers Int and String: tasks avoid these features.
- The `.triad` is the canonical extension; `.td` remains accepted as an alias.
