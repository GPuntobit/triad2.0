# TRID-070 / 071 / 074 — Quality, integration and merge safeguards

## TRID-070: epistemic invariants

Run: sh cognitive/native/tests/run_epistemic_070.sh

The committed golden cognitive/native/tests/golden_epistemic_070.view
exercises these distinct invariants:

1. Pulse is only salience: activation_pulse never contributes a proof.
2. Unobserved or missing evidence remains unknown, not refuted.
3. One of two independent source-backed proofs may be suspended while the
   other remains demonstrated_conditional.
4. Two paths sharing a correlated source cannot evade the revocation of that
   source (both must suspend; no false independence).
5. Revocation of source src_a in S0 does not revoke a same-named S1 source:
   source context and domain remain distinct.
6. An experimental rule cannot be promoted merely by changing the
   imported snapshot; no independent approval appears.
7. Reimporting identical S0/S1 input is idempotent: no new commit pointer.
8. Falsification of a ground witness fails in the independent native S0
   verifier, even when the attacker has recalculated the local polynomial
   journal chain and the outer SHA-256 manifest. This last case is exercised
   by run_integration_071.sh and requires the error "false ground proof".

Semantic reasoning and checks remain in native Triad-Core; shell stages
data and checks byte-exact outputs. No test authenticates external truth.

## TRID-071: filesystem + S0/S1 integration

Run: sh cognitive/native/tests/run_integration_071.sh

The test runs the actual native S0 discovery + independent verifier and
S1 0.6 graph resolver, imports source-backed data into the versioned
ledger, then exercises replay, repeated restarts, exact event bytes,
three independent exclusive mutexes, crash injection before S0 publication,
S1 SIGKILL after obtaining its lock and before publishing result output,
verified archived journal replay, source revocation, invalid version and
Triad-code injection rejection. All test directories are temporary.

The S1 runner uses a permanent flock inode instead of a stale mkdir lock,
so SIGKILL releases the ownership without creating a second lock inode.
Published stdout is emitted only after complete successful S1 computation.
A symlink graph or unsafe state symlink is rejected.

SIGKILL is a deterministic process interruption, not proof of correctness
under power failure on every filesystem. Independent S0 and S1 inputs are
NOT captured in a distributed atomic snapshot.

## TRID-074: always-running merge checks

Workflow: .github/workflows/trid-required.yml

No path filter: runs on every PR, including documentation-only PRs.
Ubuntu 24.04 x86_64, immutable checkout SHA, resource/time limits and
stderr diagnostic logs are used for FIVE independent jobs:

- TRID / S0
- TRID / S1
- TRID / Epistemic
- TRID / Integration
- TRID / Conformance

The always-running TRID / Merge Gate evaluates all five statuses and
fails if any one failed, timed out, was cancelled or skipped.

IMPORTANT: A green workflow does not by itself prevent merge.
GitHub must enforce branch protection independently of the workflow.

An existing disabled repository ruleset named "triad" has ID 26023880.
The inspected GitHub Actions application ID for six exact TRID job contexts
is 15368. The reviewed configuration in scripts/trid_ruleset_074.py
activates that ruleset **only for refs/heads/main** and requires:
- Pull requests (no direct pushes), no bypass actors, no branch deletion
  or force push;
- Strict, up-to-date success for TRID / S0, TRID / S1,
  TRID / Epistemic, TRID / Integration, TRID / Conformance and
  TRID / Merge Gate, all pinned to the GitHub Actions application;
- Resolution of pull request review discussions.

A solo-owner repository defaults to zero required approving reviews to
avoid making merges impossible without an eligible independent reviewer.
When there IS an independent reviewer, use --approvals 1 at first application
to additionally require approval. In both cases code review of the policy
itself before activation is required by this TRID task.

From an inspected checkout containing the script, authenticate GitHub CLI
as a repository administrator via gh auth login, then run:

    python3 scripts/tests/test_ruleset_074.py
    python3 scripts/trid_ruleset_074.py --verify
    python3 scripts/trid_ruleset_074.py --apply
    python3 scripts/trid_ruleset_074.py --verify

The initial --verify MUST fail while the ruleset remains disabled. The
--apply option refuses to overwrite an already customized ruleset and
requires GitHub Administration:write authorization; it cannot be run by
the ChatGPT GitHub connector. All tests in the source tree use mock local
data, not GitHub administrator credentials.

For the final negative verification, open a **throwaway PR** with a
deliberately mismatched golden fixture (e.g. change one byte of
cognitive/native/tests/expected_06.out). Wait until "TRID / S1" or
"TRID / Integration" is red and confirm GitHub marks the PR
**Merge blocked / Required status check failed**; do NOT merge this PR.
Close it and remove its test branch. Verify the six checks in the
GitHub ruleset after changing GitHub settings. Preserve an evidence
record with ruleset ID, main SHA, effective rules, failed check and
blocked PR URL. These are the TRID-074 final completion criteria.

GitHub's source-of-truth ruleset is server-side repository configuration,
NOT a YAML file. The linked GitHub connector can read rulesets but does
not expose ruleset writes, so ruleset activation is still pending
administrator action and TRID-074 remains OPEN until independently verified.

## CachyOS certification is separate from Ubuntu

A GitHub Ubuntu runner is not CachyOS. On a clean, real CachyOS x86_64
checkout of the exact PR commit:

    TRID_EXPECTED_SHA="$(git rev-parse HEAD)" bash cognitive/native/tests/cachyos_certify.sh

The script rejects non-CachyOS IDs and dirty checkouts, runs all five
historical suites and both new suites with time/memory bounds, captures
SHA, distro, kernel, exit statuses, timings, logs and SHA-256 manifest
in a separate temporary evidence directory. Attach the result to the PR
for review. The report is NOT remotely attested and does not prove that
all CachyOS installations behave identically.
