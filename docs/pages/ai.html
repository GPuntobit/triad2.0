The AI benchmark

The kit in the ai folder measures whether a language model is able to write Triad. It is a developer tool: it is not part of the S0 to S4 chain, the official conformance stays the one of the conformance folder, and what is measured here is the quality of the generation.

1. What it is

Inside a task there are the pieces of a small benchmark. The system prompt is given to the model, the task file is the request in natural language, the golden output is the expected standard output, the golden code is the expected exit code, zero by default, and the solution file is the program that the model produced. The model receives the prompt and a task, it answers with a Triad program, the program is saved and it is verified against the goldens.

The five tasks cover the Core subset and nothing else: the sum with its precedence, the factorial with the recursion and the ternary, the double recursion of the Fibonacci, the strings with the concatenation and the length, and a function that returns a lambda with a capture.

ai/tasks/01_somma/ println, precedence, integers ai/tasks/02_fattoriale/ functions, recursion, ternary ai/tasks/03_fibonacci/ double recursion ai/tasks/04_stringhe/ strings, concatenation, length ai/tasks/05_chiusure/ a function that returns a lambda

2. How to run it

The verifier takes every task that has a solution, runs it with the seed and compares the standard output and the exit code with the goldens. It prints a verdict for each case and a summary at the end; a missing solution is skipped and does not make the verification fail, while a single failing solution is enough to make the command exit with the code 1.

# all the tasks node cli/triad-cli.mjs ai verify # a single case node cli/triad-cli.mjs ai verify --tasks ai/tasks/02_fattoriale # with the obtained and the expected output side by side node cli/triad-cli.mjs ai verify --verbose

3. The format of the solution

The system prompt is strict on purpose: a single block of code, no text outside the block, no markdown around it, only the supported constructs of Triad-Core, no invented libraries, types or functions, and the output produced only with the print statement. The answer is saved as the solution file and it is executed by the Core interpreter.

# the answer to the task 02, as the model has to return it fattoriale(n) = n < 2 ? 1 : n * fattoriale(n - 1) println(fattoriale(5))

The metrics that can be extracted are the usual ones of the generation benchmarks: the pass at one, a single generation per task with everything green, the pass at k, with k attempts per task where the first success counts, and the classification of the failures, syntax, runtime or wrong output, to understand whether the gap is in the specification, in the examples or in the tooling.

4. How not to use it

This is a measuring instrument, not a source of implementation: the generated program is not part of the language, the repository does not take it as an implementation and the official conformance remains the one in the conformance folder. The README of the folder says it in one line: developer tool, not part of the S0 to S4 chain.

There is one real risk, and it is the reason the safety section exists: the verifier executes the generated code. A model can produce an infinite loop or an unexpected program, so the verification has to run inside a virtual machine or a container, without network and with limited resources, and an unverified output must never be pasted into production.

The rule that binds this repository is the seventh of the agent instructions: when the task is to generate a solution, return only one single block of Triad code, without explanations and without markdown, conforming to the system prompt of the folder, and verify it with the command above.
