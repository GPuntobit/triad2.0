Status

STATUS.md tracks what works today and what is missing. The short version: the standard, the conformance suite and the Windows seed are real, and the self-hosted implementation is the next milestone.

1. Ready today

  • Standard - SPEC.md version 0.2.0, SPEC-CORE.md, VERSION and CHANGELOG.md.
  • Conformance - the native POSIX conformance harness and committed Core goldens, with the goldens versioned as text.
  • Seed S0 - a Windows PE interpreter with integers, variables, functions in both forms, recursion, Bool, operators, conditionals, loops, blocks, lambdas, closures, strings and concatenation.
  • Launcher and CLI - the launcher locates the runtime for you; the Julia implementation has been removed.
  • Continuous integration - the conformance job on Ubuntu, the Windows job on the PE seed and the Linux ELF job.
  • Documentation and book - the long manual, the tutorial with its translations, and the book in PDF, EPUB, MOBI and DOCX.
  • Tooling - the editor support, the AI generation benchmark with its automatic verifier, and the small probe programs used by CI and by the install script.

2. What is missing

The seed does not implement list indexing, length and iteration, and the conversion of a value to a string covers integers and strings only. The self-hosted implementation in selfhost/ is in progress. The CLI runs files only: the REPL and the remaining options of section 14 of the standard are still to do. The native compiler, self-hosting and the parity work on Linux have not started.

3. The distance from the goal

The goal is not complete. S0 is a machine code interpreter, but S1, the interpreter written in Triad-Core, has not finished, so there is no self-hosting yet. S2 and S3, the native compiler and its fixed point, have not started, and the Linux ELF port is at its first stage. External recognition, the Linguist pull request and the publication of the extensions still depend on the maintainer: the MIT license is in place since October 2026, the rest is a step outside the repository.

4. Verification

sh conformance/run.sh # Core, 37 cases sh conformance/run.sh --cases conformance/cases # Full, 12 cases

Every change to the lexicon, to the parser, to the types, to the evaluation or to the input and output has to come with a case in conformance/ and must keep the Core cases green.

The documentation was consolidated under docs/, with the tutorial, the wiki and the security records beside the site; the small probe programs live in tests/probes/ and the legacy scaffold of the old site is still in tools/site-jekyll/. The paths that other tools depend on did not change.
