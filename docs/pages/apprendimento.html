Learning curve and threshold

Triad-Core is learned by doing, Triad-Full today only by reading. This page measures the path: the stages, their difficulty, how much of each stage can be exercised right now, and the threshold where the real mastery stops.

1. Two phases, one path

The path is built from the chapters of the tutorial and of the manual and it is made of 17 stages in three groups: 9 Core stages, 6 Full stages and 2 stages about the project itself. The Core stages cover the subset that the seed executes, so every Core chapter can be read, run and checked against its golden output. The Full stages cover the rest of the standard: of the 12 Full conformance cases only the error one passes today, so those chapters can be read but not executed.

The split is not a matter of taste, it is the runtime that decides: a chapter is exercisable only when there is a case that produces the expected bytes. The tutorial follows the same order in five parts.

Part I chapters 1-3 first steps: install, run, first program Part II chapters 4-17 Triad-Core, step by step Part III chapters 18-32 Triad-Full Part IV chapters 33-43 the project code Part V chapters 44-49 reference: grammar, quick tab, debugging, glossary, FAQ

2. The curve

Two curves are drawn on the same axis. The theoretical one measures the cumulative effort of the stages and reaches 100% at the end of the language stages: reading the whole standard is possible. The real one measures what can actually be exercised, and it tells a different story. At the threshold, the last Core stage, the idiomatic patterns and the Core exercises, it stands at 34.7% while the theoretical curve is already at 44.2%; from there the real curve creeps up to about 39% and stays there, while the theoretical one keeps climbing to the end.

3. Where the difficulty jumps

The difficulty of the Core stages goes from 29 to 56 out of 100: the lexicon and printing, the operators, the control flow, the functions, the closures, the lists and strings, the runtime errors, the idiomatic patterns. The Full stages jump to a range from 64 to 93, and the peak is the stage on the logic, with the facts, the rules and the solver, at 93: unification with occurs-check, backtracking and the solver as a value. At the same time the share exercisable today collapses: it is between 40% and 95% in the Core stages and only 8% in every Full stage.

The reason is in the nature of the language rather than in the number of pages. The Full profile adds declared types and multiple dispatch, structs, an extended flow control, the logic, the errors as values, the contracts, the budgets, the traces, the declared effects and the macros: each of them is a new way of writing a program, not a new function to call.

4. The method

  • Read the chapter, then run every Core example: the examples are the same programs as the conformance cases.
  • Write the case yourself: a deterministic program with no input, then generate the goldens and read them before committing them.
  • For a Full chapter, read the specification next to it: the standard is the contract, the case will arrive with the runtime.
  • Measure the plateau and not the number of pages: the real curve says what you can actually run today.
