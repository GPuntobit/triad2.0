Bootstrap

Triad must run without Julia, or any other language, at any stage: runtime, bootstrap or build. BOOTSTRAP.md states the requirement, the chain and the milestones that make it verifiable.

1. Why the obvious shortcuts are excluded

The requirement rules out three shortcuts. Rewriting the kernel in another language would add a dependency. Keeping a foreign runtime inside a packaged binary is still that runtime executing Triad. Committing a binary seed produced elsewhere hides the same dependency. The only coherent chain starts from an interpreter handwritten in machine code.

2. The chain from S0 to S4

S0 seed: Triad-Core interpreter in machine code (handwritten, x86-64) | executes S1 complete implementation of Triad written in Triad-Core | includes S2 native compiler written in Triad | compiles S3 self-hosted native compiler, no seed and no other language | compiles S4 complete Triad: REPL, CLI, examples, conformance

What the seed must do

The seed interprets Triad-Core and not the whole language: it reads a file and parses the lexicon, evaluates with environments and closures, carries the dynamic values, offers the arithmetic primitives and the output to the standard streams, allocates with a bump arena and exposes the entry point seed program.td. Triad-Core is chosen because it is small enough to be written by hand and expressive enough to implement the whole language on top of it.

3. S0, the seed

The seed is a PE executable for Windows x86-64 of 25088 bytes, without a runtime and without libc: it imports only a few kernel32 functions and reads the program from the first argument. Its source is an annotated hexadecimal dump kept in the repository, so the executable is materialised with a system decoder and never compiled. The Linux port exists at its E0 stage, a minimal ELF that prints its banner and exits.

certutil -decodehex seed/windows-x86_64/seed.hex seed/windows-x86_64/seed.exe seed/windows-x86_64/seed.exe conformance/core/cases/ricorsione/program.td

4. S1 and beyond

The self-hosted implementation lives in selfhost/ and is in progress: it is the interpreter of Triad-Core written in Triad-Core, with a smoke test in CI but not yet a conformance run. The native compiler and the self-hosting fixed point have not started, and the parity with the Windows seed, the REPL and the Linux ELF port are the last milestones.

5. Fixed points and development tools

The seed never contains Julia and is not produced by Julia. S1 and S2 are Triad sources versioned as text. The repository does not require Julia, Rust or C to build or use Triad. The seed generator is a maintenance tool that produces the dump: it is not part of the chain, and the goldens are committed text files, so no test needs another language.
