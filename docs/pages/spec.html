The specification

SPEC.md is the normative definition of Triad: an implementation-independent standard, versioned in the VERSION file, with its history in CHANGELOG.md. The current standard is 0.2.0.

1. What the standard defines

The specification fixes the vocabulary, the grammar, the types and the values, the semantics of functions and dispatch, logic, macros, errors, contracts, budgets, tracks, effects, the builtin set and the command line interface. Everything a conforming implementation must do is written there; the appendix at the end is informative and only lists the claimed influences.

  • §1 Vocabulary, §2 Syntax (EBNF), §3 The uniform tree, §4 Values and types.
  • §5 Functions and multiple dispatch, §6 Logic, §7 Macros and code as given.
  • §8 Errors as data, §9 Contracts, §10 Budget, §11 Tracks, §12 Effects.
  • §13 Builtin, §14 Command line interface, §15 Reference implementation status (informative).
  • §16 Compliance and versioning: profiles, verification and versioning rules.

The uniform tree

Section 3 gives the syntax tree a single shape, the uniform tree, and that is what makes the code as data of section 7 possible: a quoted expression is a value of the language, not a special case of the parser.

2. The command line interface

Section 14 fixes the shape of the triad command. The conformance suite covers the non-interactive part of it: scripts, arguments and exit codes. The REPL is covered by implementation testing.

triad # REPL triad FILE [ARG...] # run FILE; ARGS == [ARG...] triad -l FILE # load FILE and open the REPL triad -e CODE # run CODE triad --tree FILE # print the uniform tree as an S-expression triad - # read the script from stdin

3. SPEC.md and SPEC-CORE.md

SPEC-CORE.md is a normative profile of the same standard, described in §16.1: the subset that the seed must execute and in which the self-hosted implementation is written. It is not a different language with different rules. A Core program, minus the bootstrap primitives, is also a valid Full program and must behave identically. The primitives readfile, strlen, strbyte, strsub and exit exist only for the self-hosted deployment and do not appear in the Full standard.

4. How to read it

Read the standard in order if you write a runtime; skim the vocabulary, the syntax and the builtin sections if you only write programs. When a sentence and the golden cases disagree, the cases decide: the suite is the executable part of the standard, and an implementation cannot declare itself compliant without running it.

The version is written as MAJOR.MINOR.PATCH: MAJOR for incompatible changes, MINOR for compatible extensions, PATCH for corrections that do not change the behaviour. Every regulatory change updates the CHANGELOG.md and, when the behaviour changes, the goldens of the conformance suite.

Source: SPEC.md §1-§16, SPEC-CORE.md §1, §2 and §8, VERSION, CHANGELOG.md.
