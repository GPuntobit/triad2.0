Conformance

The conformance suite is the executable contract of Triad: golden cases that every implementation must reproduce byte for byte. The Triad-Core profile is green at 37 of 37 cases; in the Triad-Full profile only the error case passes today, because the rest of the full language is not implemented yet.

1. The format of a case

Each case is a directory with the program, the optional arguments and the golden outputs. The case passes when the standard output is byte for byte equal to the golden file and the exit code is the expected one. Standard error is not compared: it carries diagnostics only, and no case reads from the standard input, so the suite is deterministic.

cases/<name>/ program.td # the Triad program, run as a script args.txt # optional: one argument per line, becomes ARGS expected.out # expected stdout, exact bytes, LF line endings expected.code # expected exit code

2. The two profiles

The Core profile lives in conformance/core/cases and uses only the subset of SPEC-CORE.md, so those cases are normative for both profiles. The Full profile lives in conformance/cases and covers the whole language: struct and dispatch, facts and rules, macros, deconstruction, contracts, budgets and traces. The Full goldens were generated once and are frozen: from that moment they are the contract.

Missing goldens

The runner reads expected.out and, when it is absent, the identical copy expected.golden. When neither is there the case fails with the message golden mancante: it usually means that the checkout is incomplete, because the repository ignores the files that end with .out except the expected ones. A case can never pass without its golden.

3. Running the suite

The runner is a Node.js script with no Julia dependency. It uses the runtime given by TRIAD_SEED, otherwise the reference interpreter on Linux and macOS, otherwise the Windows seed executable.

node conformance/run.mjs # Core profile, 37 cases node conformance/run.mjs --cases conformance/cases # Full profile, 12 cases node conformance/run.mjs --skip liste # skip some cases node conformance/run.mjs --update # regenerate the goldens

Continuous integration runs the suite on every change: a job on Ubuntu with the reference interpreter, a job on the Windows PE seed with the subset of Core cases that the seed supports, and a job for the Linux ELF seed with its hash. The seed hash is checked, so a change in the machine code is always visible in the diff.

4. Adding a case

Create the directory, write a deterministic program with no input, then generate the goldens with the update option and read them before committing. The goldens are versioned together with the specification, and a missing golden makes the case fail instead of passing silently.
